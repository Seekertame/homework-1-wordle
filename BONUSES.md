# Бонусы

Сделаны все шесть бонусов из задания. Флаги бонусов можно сочетать между собой и с `--seed` и `--show-answer`. Нельзя указать вместе `--level` и `--category`. С `--replay` нельзя указывать `--seed`, `--level`, `--category` и `--record`, потому что они берутся из файла повтора.

Команды ниже для Windows. Перед запуском терминал нужно переключить на UTF-8, как описано в README.

## Уровни сложности с разными словарями

```powershell
.\gradlew.bat run -q --console=plain --args="--level easy"
.\gradlew.bat run -q --console=plain --args="--level hard"
```

Перед меню программа печатает `Уровень: лёгкий` или `Уровень: сложный`.

Сложность слова зависит от того, насколько оно распространено. Лёгкий уровень загадывает слова из списка распространённых слов, которые знает каждый, например `озеро` или `школа`. Список отобран вручную, в нём 175 слов. Он лежит в файле `src/main/resources/levels/easy.txt`. Сложный уровень загадывает все остальные слова словаря, их 469. Так одно слово не может оказаться в двух уровнях сразу, и новое слово нужно добавлять только в один список.

Уровень меняет только то, из каких слов загадывается ответ. Ввод по-прежнему проверяется по всему словарю, поэтому на лёгком уровне можно вводить любые слова.

Уровни описывает enum `Level`. Его метод `answers` возвращает слова уровня. Он загружает список лёгких слов и проверяет, что все они есть в общем словаре. Для партии с отдельным набором ответов есть `Game.startGame(dictionary, answers, maxAttempts, seed)`: ответ берётся из `answers`, а ввод проверяется по `dictionary`. Обязательная сигнатура `startGame(dictionary, maxAttempts, seed)` осталась и просто передаёт весь словарь как набор ответов. Поэтому без флагов игра работает как раньше.

Тесты в `LevelTest`: лёгкий уровень совпадает со списком, в сложном нет ни одного слова из списка, вместе они делят словарь без остатка, партия загадывает слово своего уровня.

## Категории слов

```powershell
.\gradlew.bat run -q --console=plain --args="--category animals"
```

Перед меню программа печатает название категории, например `Категория: Животные`.

Категорий шесть: `animals` (животные), `food` (еда), `nature` (природа), `home` (дом и быт), `clothes` (одежда) и `people` (люди и профессии). Слова для них отобраны вручную. Слова каждой категории лежат в своём файле в папке `src/main/resources/categories`, например `animals.txt`. Формат файла такой же, как у `dictionary.txt`, поэтому он загружается тем же методом `Dictionary.load`.

Каждое слово категории есть в общем словаре и входит только в одну категорию. Это проверяют тесты. При запуске программа ещё раз проверяет, что все слова категории есть в словаре, иначе партия упала бы в момент выбора слова.

Уровень и категорию нельзя указать вместе. Пересечение могло бы оказаться очень маленьким или пустым.

Категории описывает enum `Category`, устроенный так же, как `Level`.

Тесты в `CategoryTest`: слова каждой категории есть в словаре, категории не пересекаются, партия загадывает слово своей категории, каждая категория есть в подсказке запуска.

## Подсказка к слову

Во время партии нужно ввести `?`. Программа откроет одну букву ответа:

```text
Подсказка: на 1 месте буква ш
```

Правила подсказки:

1. Открывается первое место, где игрок ещё ни разу не получил ✅.
2. Подсказка не тратит попытку.
3. В партии подсказка одна. На второй `?` программа отвечает, что подсказка уже использована.
4. Если все места уже найдены, подсказывать нечего. Тогда подсказка не расходуется.

Правила подсказки лежат в пакете `game`, а консоль только узнаёт команду и печатает результат. Метод `Game.hint(session)` возвращает `Optional<Hint>`. `Hint` это record с местом и буквой. Пустой `Optional` значит, что все места уже найдены. Признак «подсказка использована» хранится в партии, в поле `hintUsed`, потому что это часть её состояния.

Консоль проверяет `?` до вызова `Game.applyGuess`. Иначе `?` считался бы словом неправильной длины. Строка `?` вынесена в `Constants.HINT_COMMAND`. В начале каждой партии программа пишет, как получить подсказку.

Тесты в `HintTest` и `ConsoleGameTest`: первая буква без попыток, найденные места пропускаются, попытка не тратится, вторая подсказка не даётся, при всех найденных местах подсказки нет, в завершённой партии подсказки нет.

## Статистика игрока за запуск

При выходе через пункт меню «2» программа печатает итоги запуска:

```text
Сыграно партий: 2. Побед: 1 (50%).
```

Если не сыграно ни одной партии, строка не печатается. Процент округляется вниз, поэтому 2 победы из 3 партий дают 66%.

Счётчики хранит класс `Statistics` в пакете `game`, потому что подсчёт не связан с вводом и выводом. Он учитывает только завершённые партии. Партия, которая ещё идёт, даёт ошибку. Партия, прерванная концом ввода, не учитывается. Печатает статистику `ConsoleGame`.

Тесты в `StatisticsTest` и `ConsoleGameTest`: пустая статистика, победа и поражение, округление процента, ошибка на незавершённой партии, строка при выходе, отсутствие строки без партий.

## Цветной вывод

```powershell
.\gradlew.bat run -q --console=plain --args="--color"
```

Буквы попытки печатаются на цветном фоне, как в настоящем Wordle. Зелёный фон значит ✅, жёлтый 🟡, серый ❌. Значки в начале строки остаются.

Цвет включается флагом и по умолчанию выключен. Формат вывода из задания фиксирован, и обязательные тесты его проверяют, поэтому без флага вывод не меняется.

Цвет задаётся кодами ANSI. Это специальные последовательности символов, которые терминал не печатает, а воспринимает как команду сменить цвет. Например, `\u001B[42m` включает зелёный фон, а `\u001B[0m` возвращает обычный цвет. Коды лежат в `Constants`. Цвет для статуса выбирается в `ConsoleGame` через `switch` по `LetterStatus`.

Цвета работают в Windows Terminal, в PowerShell на Windows 11 и в консоли IntelliJ IDEA. В старом cmd вместо цвета могут появиться символы вроде `←[42m`.

Тесты в `ConsoleGameTest`: с флагом в выводе есть коды всех трёх цветов и значки, без флага кодов нет.

## Replay по seed и списку попыток

Игра полностью повторяема. Одинаковый seed даёт одинаковое слово, а одинаковый ввод даёт одинаковые ✅🟡❌. Поэтому по seed и списку попыток партию можно воспроизвести точь-в-точь.

### Запись

С флагом `--record` программа сама сохраняет каждую завершённую партию:

```powershell
.\gradlew.bat run -q --console=plain --args="--record"
```

После каждой партии она пишет, куда сохранила повтор:

```text
Победа! Слово угадано за 2 попытки
Повтор сохранён: replays\game_-5843495416241995736.txt
```

Файлы лежат в папке `replays` в той папке, из которой запущена программа. При запуске через `gradlew.bat run` это корень проекта. Папка добавлена в `.gitignore`, повторы не попадают в коммиты.

Файл повтора выглядит так:

```text
# Повтор партии «5 букв». Запуск: --replay <путь к этому файлу>
seed -5843495416241995736
?
качан
арбуз
гарем
```

В нём лежит seed именно этой партии, а не всего запуска. Поэтому можно повторить любую партию запуска, а не только первую. Если в игре были `--level` или `--category`, в файл пишется строка `level easy` или `category food`. Дальше идёт всё, что игрок ввёл за партию: попытки, подсказки и отклонённые слова. Пустые строки не записываются.

Партия, прерванная концом ввода, не сохраняется. Если сохранить файл не удалось, программа сообщает об этом, и игра продолжается.

Запись включается флагом, а не всегда. Иначе обычная игра оставляла бы файлы в папке запуска, а каждый прогон тестов создавал бы их в папке проекта.

### Повтор

```powershell
.\gradlew.bat run -q --console=plain --args="--replay replays\game_-5843495416241995736.txt"
```

Программа без меню проигрывает партию из файла и печатает тот же вывод, что и при обычной игре:

```text
Повтор партии
Угадайте слово из 5 букв. Попыток: 6
Для подсказки введите ?
Подсказка: на 1 месте буква г
Такого слова нет в словаре. Попытка не потрачена.
🟡🟡❌❌❌ арбуз
Осталось попыток: 5
✅✅✅✅✅ гарем
Победа! Слово угадано за 2 попытки
```

Правила повтора:

1. Seed, уровень и категория берутся из файла. Указывать их флагами вместе с `--replay` нельзя, программа сообщает об ошибке.
2. `--color` и `--show-answer` с повтором работают.
3. Ввод после конца партии не используется.
4. Если ввод кончился раньше конца партии, программа сообщает, что партия не завершена.
5. Путь к файлу считается от папки, из которой запущена программа. Если файла нет, программа печатает полный путь, по которому его искала, и завершается с кодом 2. Если в файле нет строки `seed`, тоже.
6. Файл можно написать и вручную: строка `seed число`, потом попытки по одной в строке. Строки с `#` и пустые строки пропускаются. Невидимый символ BOM в начале файла, который добавляют Блокнот и PowerShell 5.1, тоже пропускается.
7. Имя файла лучше писать латиницей. Кириллица в аргументах запуска на Windows может не дойти до программы, это та же причина, по которой нет `--answer`. Сами попытки в файле можно писать по-русски, файл читается в UTF-8.

### Как устроено

Запись партии описывает record `Replay` в пакете `console`: seed партии, уровень, категория и ввод игрока. Он умеет сохранять себя в файл и читать из файла. Строки `seed`, `level` и `category` читаются только в начале файла, до первой строки ввода. Иначе слово игрока, похожее на настройку, изменило бы партию.

Чтобы знать seed каждой партии, `GameSeries` запоминает seed последней начатой партии, метод `lastSeed`. По этому seed `Game.startGame` загадывает то же самое слово, что и серия.

`ConsoleGame` собирает всё, что игрок ввёл за партию, и после её конца передаёт в интерфейс `GameRecorder`. Сама консоль не знает, куда и как сохраняется партия. Реализацию передаёт `Main`: она создаёт `Replay` с seed партии и сохраняет его в папку `replays`. В тестах вместо неё подставляется лямбда, которая просто запоминает ввод.

Повтор переиспользует обычный код партии. В `ConsoleGame` есть закрытый интерфейс `GuessSource`: откуда брать следующую строку. При обычной игре строки читаются с клавиатуры, при повторе берутся из списка. Метод `playGame` один для обоих случаев, поэтому вывод при повторе совпадает с обычным.

Тесты:

- `ReplayTest`: сохранение и чтение без потерь, категория в файле, пропуск BOM, комментариев и пустых строк, настройки после ввода считаются вводом, ошибки на файле без seed, с неверным seed и с уровнем и категорией сразу.
- `ConsoleGameTest`: в запись попадает весь ввод завершённых партий, незавершённая партия не записывается, ошибка записи не прерывает игру, повтор проигрывает ввод и не показывает меню, лишний ввод не используется, при нехватке ввода выводится сообщение.
- `GameSeriesTest`: по `lastSeed` партию можно начать заново.
- `MainTest`: две партии с `--record`, потом повтор второй из сохранённого файла через запуск программы, файл вручную с BOM, ошибки при отсутствии файла и без seed.
- `LaunchOptionsTest`: `--replay` вместе с `--seed`, `--level`, `--category` или `--record` даёт ошибку.
